# 四人任务与一个月时间线

## 共同目标

四部分工作合并后，系统必须完成同一条学习闭环：

`前测或作答 -> 判断学习情况 -> 查找官方资料 -> 生成内容 -> 检查内容 -> ECHO 展示 -> 判分 -> 更新学习情况 -> 安排下一步`

培训领域固定为“基于 Microsoft Semantic Kernel 的企业级智能体应用开发”。系统只保留三个学习模块、四个后台 Agent、三种个性化资源和 50 组固定评测，不增加装饰性功能。

## 成员 A：主系统、ECHO、检索引擎与总集成

需要完成：

- 维护比赛仓库、数据库、登录权限、会话、三个模块和公共页面。
- 保留并完善 ECHO 的解释、追问、提示、反思和进阶流程；每轮只做一个主要动作。
- 完成学习情况分析、内容生成、内容检查和下一步安排四个后台 Agent 的调用顺序与记录。
- 完成基于多路召回与混合向量的可追溯 RAG 检索引擎，包括材料切片、导入、检索、重排、引用和异常降级。
- 恢复固定题库导入，支持模块、知识点、用途、难度、答案、评分方法、官方出处和是否更新 MIRT。
- 完成固定前测、模块后测、动态出题、服务器判分、重复提交保护和会话恢复。
- 根据 C 给出的知识点、难度、内容形式和理由，生成三种个性化资源，并用 D 的标准进行独立检查。
- 接入 B 的微表征结果、C 的学习总结和 SimpleMem、D 的材料题库与评测参考数据。
- 批量运行 50 组案例，计算内容错误率、难度匹配率、知识点覆盖率和出处可查率。
- 完成学习者页面、讲师页面、Demo 模式、部署和最终演示。

完成标志：

- 四部分功能可以在一个系统中连续运行。
- 四个后台 Agent 的输入、结果、失败原因和最终决定可以查看。
- 没有官方资料时不生成带引用的正式内容。
- 重复提交不重复计分，服务重启后学习进度可以恢复。
- 50 组案例可以重复运行并生成四项指标和失败清单。

不负责：修改 MIRT 算法、实现 SimpleMem 内部功能、重新训练微表征模型、撰写课程材料和题目。

## 成员 B：把现有微表征检测接入产品

需要完成：

- 接入学习者单段录音和讲师批量录音。
- 返回任务状态；失败时说明文件、格式、授权或服务原因。
- 每条结果写清用户或课次、开始和结束时间、类型、可信程度、简短文字和确认状态。
- 合并重复结果，过滤低可信结果；无法确认说话人时只进入课次统计。
- 输出各类信号次数、总停顿时间、前后变化和待确认数量。
- 只把已确认结果交给 C；把时间点和课次汇总交给 A 展示。
- 使用已有标注数据计算准确率、召回率和 F1，并说明常见误检、漏检。
- 准备 10 组覆盖三类学习者和三个模块的差异案例。

完成标志：

- 每条结果都能回到原录音时间。
- 未授权录音不分析，未确认说话人不进入个人档案。
- 同一录音重复提交不重复统计。
- 微表征只影响提示方式和判断依据，不判断专业答案，也不修改 U/A/R。

不负责：重新训练检测模型、学习 Semantic Kernel 课程内容、实现 MIRT 或题目判分。

## 成员 C：MIRT、学习总结、个人报告与 SimpleMem

需要完成：

- 按 M1、M2、M3 分别维护理解、应用和推理三项能力。
- 只有已经判分且允许更新能力的题目才能更新 MIRT；同一提交编号只计算一次。
- 根据作答记录整理已掌握知识点和知识盲区，没有作答证据时不强行判断。
- 输出固定的学习情况总结：能力现状和变化趋势、有作答依据的知识盲区、推荐难度、
  下一知识点、推荐内容形式、推荐辅导方式、推荐原因和证据来源。
- 个人报告固定分为“能力与变化、证据与盲区、路线与资源”三部分。
- 大模型只负责把统计结果写成易懂文字；模型不可用时使用固定模板，不让报告空白。
- 向 A 提供当前最需要的一项内容决定，避免同时生成多份无关资源。
- SimpleMem 保存经常出现的错误、学习偏好和过去有效的辅导方式。
- SimpleMem 支持新增、查找、修改、删除、合并、权限隔离和异常降级。
- 准备 P1、P2、P3 三类学习者样例和 10 组跨多次学习的记忆差异案例。

完成标志：

- 每条盲区、难度和路线建议都能找到题目、得分、时间或长期记录。
- 微表征和记忆不直接修改 U/A/R。
- P1、P2、P3 在相同模块中能得到有理由的不同建议。
- SimpleMem 不可用时，数据库中的答题和能力结果仍能使用。

不负责：微表征模型、课程材料、题目生成、公共数据库迁移和公共导航。

## 成员 D：官方材料、固定题库和评测参考数据

需要完成：

- 明确 M1、M2、M3，每个模块整理 4 至 6 个主要知识点。
- 只使用 Microsoft Learn Semantic Kernel 文档、官方仓库和官方示例。
- 保存完整原文，并记录资料名称、官方链接、版本或日期、所属模块和相关章节。
- 为 P1、P2、P3 说明同一知识点应采用的讲解深度、步骤多少和题目难度。
- 准备至少 27 道固定前测题、27 道模块后测题和 9 道操作题，共 63 道。
- 每道题写清用途、题干、答案、评分方法、难度、知识点、官方出处和是否允许更新 MIRT。
- 为定制学习资料、实践操作指南和阶段测试准备内容要求与检查标准。
- 准备 36 组基础对话、9 组动态调整和 5 组异常情况，共 50 组。
- 每组写清学习者、模块、对话输入、预期动作、知识点、难度、官方出处、回复特点、是否发布和是否更新 MIRT。
- 分别标出内容错误、难度不匹配、知识点遗漏和出处不可查，供 A 计算四项指标。

完成标志：

- 三个模块、三类学习者和三种资源都有清楚对应关系。
- 63 道固定题都能导入正确模块和知识点。
- 每道题都有可执行的答案与评分方法，不使用“由系统判断”等模糊表述。
- 50 组案例覆盖三类学习者、三个模块、动态调整和异常情况，并有明确参考结果。

不负责：检索引擎代码、资源和题目生成代码、内容检查程序、评测运行程序、MIRT、SimpleMem 和微表征系统。

## 一个月时间线

| 时间 | A | B | C | D |
|---|---|---|---|---|
| 第 1 周前两天 | 提供主系统接入位置和公共数据要求 | 提供一组完整检测结果 | 提供一组完整学习总结 | 提供一个模块的材料和题目样例 |
| 第 1 周后五天 | 恢复题库导入并打通 Mock | 接通录音与任务状态 | 确定能力更新、报告和记忆规则 | 完成模块、知识点和官方材料清单 |
| 第 2 周 | 完成检索、生成、检查、出题和评分主流程 | 真实录音返回结果 | 完成能力、盲区、难度和记忆查询 | 完成 63 道固定题及评分依据 |
| 第 3 周 | 接入三方功能、页面、Agent 记录和评测入口 | 完成课次汇总和 10 组案例 | 完成三部分报告和 10 组记忆案例 | 完成三种资源标准和 50 组评测数据 |
| 第 4 周前半 | 运行 50 组案例并计算四项指标 | 完成识别效果和异常测试 | 完成三类学习者、权限和异常测试 | 核对检索、导入和实际评测结果 |
| 第 4 周后半 | 统一修复、部署和演示 | 配合修复并冻结交付 | 配合修复并冻结交付 | 修正材料与参考结果并冻结交付 |

## 合并顺序与边界

1. A 先提供主系统接入位置和数据要求。
2. B、C、D 先交一组最小可用样例，再继续完成全部内容。
3. 每部分先通过自己的测试，再提交合并申请。
4. A 负责公共数据库迁移、公共导航、主应用入口和最终合并。
5. 公共字段或接口需要变化时，先修改说明和测试，再修改实现。
6. 第 4 周只修复指标与稳定性问题，不增加新功能。
