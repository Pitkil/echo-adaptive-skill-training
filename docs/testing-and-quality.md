# 测试与质量门禁

## 自动检查

```powershell
python -m ruff check apps services tests
python -m pytest -q
python -m compileall -q apps/api services
docker compose config
```

`services/punditrag/` 保留上游项目的代码风格，不纳入根 Ruff 自动改写；CI 使用其锁定依赖单独执行
6 个离线确定性回归脚本，并与根项目一起进行 Python 编译和 Compose 校验。

## 必测边界

- 问候和结束只匹配独立短句。
- 每轮只有一个主要动作。
- 有效前测或可判分答案才更新 U/A/R。
- 前测、阶段测验、后测和练习题不得跨用途混抽。
- 题目接口不得返回答案或评分方法，正确性必须由服务器计算。
- 作答记录必须保存原始答案、分数和是否正确。
- 相同 `attempt_id` 不重复更新能力、历史和日度统计。
- 微表征和 SimpleMem 不直接改变 U/A/R。
- 三个洞察视图读取真实接口，每条盲区、难度和路线建议都能找到证据。
- 大模型不可用时，学习报告使用固定模板并保留完整统计结果。
- 学习者与讲师录音都产生可定位任务和事件。
- 未授权录音、未绑定说话人不进入个人画像。
- 同一录音重复提交不重复分析和重复计入课次汇总。
- 内容生成与内容检查分别保存结果；检查失败时只重做有问题的部分。
- 服务重启后会话上下文可恢复。
- 三个外部服务异常时有明确降级。

## 比赛评测

D 维护 50 组冻结案例，覆盖三类学习者、三个模块、三类资源和失败重试。

| 指标 | 目标 |
|---|---:|
| 内容错误率（幻觉率） | `< 5%` |
| 难度匹配率 | `>= 85%` |
| 核心知识覆盖率 | `>= 90%` |
| 出处可查率 | `100%` |
| 闭环记录完整率 | `100%` |

指标脚本必须输出案例编号、版本、失败原因和可复现结果，不能只输出总分。
