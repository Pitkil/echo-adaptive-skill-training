## 必须补齐的交付

### D1. 准备正式官方材料包

新增 `docs/member-d/official_materials_manifest.json`。每份材料至少记录：

- `material_id`、资料名称和资料类型。
- Microsoft Learn 或 `microsoft/semantic-kernel` 官方来源链接。
- 版本、提交号或获取日期。
- `module_id`、相关 `knowledge_point_id` 和具体章节。
- 本地原文文件名、文件格式、内容哈希和是否已完成导入核对。

完整原文应放入供管理端导入的私有材料包，例如 `data/official-materials/`，不要把上传文件、
大体积材料或可能受许可限制的副本直接提交到 Git。Git 中提交清单、哈希和来源信息即可。

材料必须满足：

- 只来自 Microsoft Learn Semantic Kernel 文档、官方仓库或官方示例。
- 三个模块和 12 个知识点都有至少一份可定位的官方依据。
- 链接可打开，章节与题目或资源所引用的结论一致。
- 优先使用稳定的官方规范链接；非默认语言链接应确认不会影响演示和人工核对。
- 不使用博客、问答网站或模型生成内容作为标准答案。

新增 `docs/member-d/material_import_verification.md`，记录材料编号、导入状态、返回的来源链接、
章节定位和失败原因。D 负责核对内容，A 负责实际检索引擎与导入程序。

### D2. 冻结 63 道正式题

- 27 道 `pretest`。

现有另外 3 道操作题可以保留为候选题，但必须在清单中标记为非正式、不得进入本次正式

清单中的每道题至少记录：

- `module_id`、`knowledge_point_id`、用途、题型和难度。
- 答案、可执行评分方法和满分。

### D3. 合并并冻结三类资源检查标准

将 D 分支中的 `docs/member-d/resource_checklist.md` 整理后提交 PR。检查标准必须分别覆盖：

- 定制学习资料：知识点准确、解释深度、难度和引用。
- 实践操作指南：前置条件、步骤可执行性、预期结果、错误处理和引用。
- 阶段测试：题目范围、难度、答案与评分规则的服务端保存边界。

每类资源都要明确：

- 必须通过项、可修改项和禁止发布项。
- 内容错误、难度不匹配、知识点遗漏和出处不可查的判断规则。
- 没有官方证据时只能保存为草稿。
- P1、P2、P3 的讲解深度、步骤多少和题目难度。
- 检查失败时需要重做的具体部分，不能只写“重新生成全部内容”。

D 只提供标准和参考结果，A 负责把标准实现为内容检查和局部重做程序。

## 负责人 A 接管修正时的规则

工期紧张时，A 可以接管 D 的收尾，但应明确记录“负责人接管内容数据修正”，避免责任和
提交历史混乱。

推荐流程：

1. 先让 D Push 当前分支并说明尚未完成项。
2. A 在 `member/a-integration` 同步最新 `origin/main`。
3. 通过普通合并或挑选提交引入 D 的有效文件，保留原作者历史。
4. A 在自己的分支修复 63 题清单、50 组数据和材料清单。
5. 运行校验和项目质量门禁后创建 PR，不直接推送 `main`。

不要直接改写或强制推送 `member/d-content-data`，也不要覆盖 D 尚未合并的提交。建议使用
`fix(content-data): freeze formal quiz and evaluation data` 作为负责人修正 Commit。

## 提交建议

如果仍由 D 完成，建议拆成四个可独立审核的 Commit：

1. `docs(materials): add official material manifest and verification`
2. `fix(quiz-data): freeze 63 formal questions`

全部修改提交到 `member/d-content-data`，创建目标为 `main` 的 PR。PR 必须写清材料包位置、
正式题数量、50 组分布、验证结果以及需要 A 完成的导入和运行工作。

## 完成判定

以下条件必须同时满足，D 才能标记完成：

- 正式官方材料清单完整，原文包可供导入，来源和章节可追溯。
- 正好 63 道正式题通过预览核对，模块、知识点、答案和评分方法完整。
- 三种资源检查标准进入 `main`，并包含 P1、P2、P3 的差异要求。
- 50 组评测数据数量、编号、36/9/5 分布和参考结果全部正确。
- D 相关静态数据检查及项目完整质量门禁通过。
- PR 已由负责人审核并合并。
